## Definition of done

### Phase 1: Hooks bank
Paste:
> Write 30+ hooks across the pillars using the researched patterns. Audit each as a cold scroller: would the first line stop the thumb? Kill the bottom third. The survivors (20+) go in CONTENT-SYSTEM.md tagged by pillar and format.

### Phase 2: The batch, with per-post loops
Paste:
> Draft all 30 days: each post = hook from the bank + body in the platform's native format + CTA where it earns one. Per post: de-slop loop, then the platform audit against the post checklist below. Batch in weeks; re-read each week's set together for repetition drift.

### Phase 3: Visuals (where configured)
Paste:
> Generate the visual per post that needs one, against a single style anchor defined once (palette, composition rules, text-overlay style). Audit each at phone size: legible, on-brand, consistent with the set. Video posts get scripts routed through the video harness short-form path.

### Phase 4: Operating loop handoff
Paste:
> Produce the calendar (post, day, time in the account's timezone), a scheduling note for the user's tool of choice, and WEEKLY-LOOP.md: the 30-minute weekly ritual (approve next week, read this week's numbers, tag winners, feed winning patterns back into CONTENT-SYSTEM.md). Verify all 30 posts + visuals exist per PROCESS-CORE.md before reporting done.

## Post checklist

1. The hook stops the thumb in the first line (first ~8 words); the weakest hook variants were killed.
2. Native to THIS platform: length, formatting (line breaks, carousel, caption), and rhythm — never a cross-post.
3. De-slopped: no AI tells (rule-of-three, inflated symbolism, hollow transitions, "in a world where…").
4. One idea per post; it delivers value or a reason to follow before it asks for anything.
5. CTA discipline: an ask only where it's earned (cadence set by the goal), not on every post.
6. Ties to a declared pillar; the week's set doesn't repeat itself.
7. Any visual is legible at phone size and consistent with the style anchor.
