## Definition of done

- POSITIONING.md exists: who, pain, offer, price hypothesis, kill criterion (what result within what window means stop).
- Brand kit exists and doesn't look default: name checked for collisions, wordmark, palette, type pair.
- Landing page live at a real URL, passing the website design checklist.
- Outreach machine loaded: target list (50+ where outbound), sequenced copy that passed the de-slop loop, and a tracking sheet.
- A launch-week runbook telling the human exactly what to do each day with the machine.

## Phases

### Phase 0: Positioning interrogation (fresh session)
Paste:
> Read HARNESS.md and PROCESS-CORE.md. Interrogate the business before building anything. Produce POSITIONING.md: (1) the buyer, specific enough to find 50 of them; (2) the pain in the buyer's words, not category language; (3) the offer and price hypothesis; (4) why they'd pick this over doing nothing; (5) the kill criterion. Where the interview answers are thin, run a quick research loop on the market instead of inventing. Flag every assumption that only real buyer contact can settle.

USER GATE: approve POSITIONING.md. Every downstream asset is generated FROM this file; fixing it later means regenerating everything.

### Phase 1: Brand kit
Paste:
> From POSITIONING.md: shortlist 5 names (check domain + rough trademark collision via search), pick, then build the minimal brand kit: wordmark, palette, type pair, one-line description that passed the de-slop loop. Restraint reads expensive; skip mascots, gradients-everywhere, and mood-board sprawl. Write to brand/.

### Phase 2: Landing page
Paste:
> Build the landing page by running the WEBSITE harness phases 1-4 (its template ships alongside this file) with POSITIONING.md as the copy source. The page's one job: get the buyer to the single next step (call, waitlist, purchase). Voice-of-customer language beats clever copy.

### Phase 3: The customer machine
Paste:
> Build the acquisition machine per HARNESS.md config. Outbound: target list from free-tier discovery (search-only tools for names, cheap enrichment for contacts; never pay where a free tier exists), a 3-touch sequence in the buyer's language (de-slop loop mandatory, AI-sounding outreach is deleted on sight), and a reply playbook. Content: pillars + hooks bank + first week's posts via the social-content harness. Ads: 2 hero variants + ad copy kit against POSITIONING.md.

### Phase 4: Launch runbook and handoff
Paste:
> Write LAUNCH-WEEK.md: day-by-day operator instructions (what to send, post, measure; what number triggers the kill criterion vs doubling down). Then the honest-gaps section: everything this machine can't know until real buyers respond. Verify every asset exists and works per PROCESS-CORE.md before reporting done.
